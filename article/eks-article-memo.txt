② EKS クラスター作成
※ この時点ではまだアプリはデプロイしません

まずはAWSでの環境の構築を行います。
今回はあくまで試験的な環境作成のため、最小の構成になっています。
(図を作成する)
必要なのは
- VPC
- Public subnet x2
- Private subnet x1
- Internet gateway x1
（- NAT gateway x1）←削除←クラスターは public subnet に配置するため
インスタンスのサイズは t3.medium

Route table は
共通設定：destination が VPC の CIDR ならば local を Target に

Destination: VPCのCIDR → local
Destination: 0.0.0.0/0     → Internet Gateway

private subnet の場合、
Destination: 172.31.0.0/16 → local

(何度か失敗する)
失敗① vpc-cni でエラーメッセージ
原因
Kubernetes では本来、 Pod は「仮想ネットワーク」の IP を持つクラウドの VPC とは切り離されているのですが、EKS では Pod を VPC に直接つなぎたいという要望がありました。
そのため Amazon では VPC CNI plugin を使っています。
vpc-cni は EC2 の ENI（ネットワークカード）を使い、 Pod に VPC CIDR の IP を直接割り当てます。
解決策
cluster.yaml ファイルに以下の設定を追加する。
iam:
  withOIDC: true


失敗② NAT gateway の設定忘れ
以下のようなエラーメッセージが表示されました。
Resource handler returned message: "[Issue(Code=Ec2SubnetInvalidConfiguration, Message=One or more Amazon EC2 Subnets of [subnet-xxx] for node group spot-ng does not automatically assign public IP addresses to instances launched into it. If you want your instances to be assigned a public IP address, then you need to enable auto-assign public IP address for the subnet.

原因
Private Subnet の Node / Pod は：
自分では Public IP を持たないが ECR から image を pull し、AWS API にアクセスし、OS パッケージ取得するためにインターネットへの出口が必要で、そのためには NAT Gateway です。
解決策
NAT gateway を public subnet に配置、type は public で elastic IP アドレスの設定を行います。

失敗③ Instances failed to join the kubernetes cluster,
原因
解決策
Node instance role を明示的に作り、Node Group に使わせる
１．Node 用 IAM ロールを手動で作成
AmazonEC2ContainerRegistryReadOnly
AmazonEKS_CNI_Policy
AmazonEKSWorkerNodePolicy
を設定すること
２，cluster.yaml でそのロールを明示指定
    iam:
      instanceRoleARN: arn:aws:iam::000000000000:role/webgame-eks-node-instance-role
３，Network ACL をデフォルトに戻す
HTTPS で通信する必要があるがポート443を閉じていた＋戻り通信（非常に重要）Ephemeral ports（1024–65535）も閉じていた
４．一度「eksctl delete cluster --region=us-east-1 --name=webgame-cluster」コマンドを実行後に
再度「
source eks/cluster-values.yaml
eksctl create cluster -f cluster.yaml
」コマンドを実行する。

③ RDS 接続用の Security Group 設計
目的（何を守りたいか）
- EKS 上の Pod だけが RDS に接続できる
- IP アドレスに依存しない（Pod / Node が変わっても壊れない）
-「0.0.0.0/0」は使わない

SG-to-SG 参照を使います。
RDSへ設定するSGは、EKSクラスターを作成した時に、自動で作られたインスタンスに付与されているSGからのアクセスを許可する
RDS の inbound に許可すべきなのは EKS Node（EC2）に付与されている SG


eksctl create cluster -f cluster.yamlコマンドで作成された EC2 の security group を確認
eks-cluster-sg-webgame-cluster-1415734157

RDS の security group を確認
WebGame-EKS-RDS-SG

configmap と secret の作成

つまり Spring Boot では環境変数だけを見るようにし、その環境変数を CircleCI では CircleCI の environment variable から
